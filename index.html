A step-by-step guide to creating a skill that reads session transcripts and produces a reusable how-to slide deck — for any Cowork user.

What you're building

The Reverse Engineer Skill

A Cowork skill that reads one or more session transcripts and produces a polished HTML slide deck explaining what was built and how to recreate it from scratch.

Why it matters

→

Turns private session knowledge into shareable tutorials

→

Anyone on your team can recreate any build — without asking you

→

Works across single sessions and multi-session projects

→

Output is a self-contained HTML file — no server, no dependencies

Before you start

What you'll need

Cowork access
You need an active Cowork session. The skill will live in your Cowork skills folder.
A slideshow skill
The reverse engineer skill delegates HTML output to a slideshow skill. You'll build a simple one as part of this guide.
Session IDs to test with
Have 1–2 session IDs ready to run your first test. You'll learn how to find them on the next slide.
A text editor (optional)
Helpful for reviewing the SKILL.md files you create. VS Code or any plain-text editor works fine.
Foundation concept

Session IDs & Transcripts

Every Cowork conversation is stored as a "session". Each has a unique ID and a full transcript of every message exchanged.

The reverse engineer skill reads these transcripts to extract what was built, which tools were used, and what prompts drove the work.

Finding session IDs

1.

Ask Claude: "Show me my recent sessions" — it will list titles and IDs

2.

IDs look like: local_a54f528a-b854-4fe4...

3.

For multi-session projects, collect all relevant IDs before running the skill

The skill uses mcp__session_info__list_sessions and mcp__session_info__read_transcript — these are built-in Cowork tools, no extra setup needed.

Overview

Two skills, working together

The reverse engineer skill delegates the visual output to a separate slideshow skill. You need both.

1. The Slideshow Skill
Contains the CSS/JS template, layout rules, and slide patterns for building HTML decks. The reverse engineer skill reads this to know how to build the output.
2. The Reverse Engineer Skill
Reads session transcripts, extracts what was built, and uses the slideshow skill to produce a how-to deck. This is the main skill you're creating.
Skill format
Each skill is a folder with a SKILL.md file inside. You zip it into a .skill file to install it.
Where skills live
Once installed, skills appear in Claude's available skills list and are read automatically when relevant prompts are typed.
Building the skill · Step 1 of 5
1
Create your slideshow skill
In a new Cowork session, type the prompt below. Claude will build a SKILL.md file containing the complete HTML/CSS/JS template for building slide decks, plus layout rules and slide patterns. Save it to your skills folder.
Prompt to type
Create a skill called "html-slideshow" that teaches Claude how to build self-contained HTML slide decks. Include: a fixed 960×540px layout scaled by JS, full CSS variables for colours, navigation with dots and arrow keys, and at least 5 slide patterns (cover, two-column, grid cards, step slide, dark/code slide). The skill should document all layout rules that caused debugging issues (e.g. never use flex:1 on content boxes, never put two layout classes on the same element). Save the SKILL.md to my skills folder.
Building the skill · Step 2 of 5
2
Create the reverse-engineer SKILL.md
Type the prompt below to have Claude write the SKILL.md for your reverse engineer skill. This is the core instruction file. Claude will create a folder called reverse-engineer/ with a SKILL.md inside.
Prompt to type
Create a SKILL.md for a skill called "reverse-engineer". It should: 1. Use mcp__session_info__list_sessions to show recent sessions if no ID is provided, and mcp__session_info__read_transcript (limit: 100) to read each transcript. 2. Analyse what was built — extracting a full inventory: every skill triggered, every connector used, every folder connected, every file uploaded or created, and any key techniques (e.g. iterative refinement, subagents, screenshots uploaded for reference). 3. Identify the minimum steps to recreate the build from scratch — stripping out dead ends and wrong turns from the transcript, leaving only what worked. 4. Read the html-slideshow skill, then produce a self-contained HTML slide deck containing: (a) what was built and why it's useful, (b) full checklist of what the reader needs before starting, (c) step-by-step instructions with verbatim copy-paste prompts for each step, (d) key prompts labelled by what they achieved, (e) tips and watch-outs, (f) a closing call to action. Save to my skills folder as reverse-engineer/SKILL.md.
Building the skill · Step 3 of 5
3
Review and refine
Read the generated SKILL.md and check these five things. If anything is missing or wrong, ask Claude to fix it directly.
✓

Frontmatter description — Does it clearly describe when to trigger the skill? Include phrases like "reverse engineer this session", "how was this built?", "show me how to recreate X".

✓

Inventory checklist — Does it explicitly extract skills, connectors, folder access, uploaded files, created files, and techniques used?

✓

"Straightest path" instruction — Does it say to strip out dead ends and only show the steps that actually worked?

✓

Slideshow skill reference — Does it tell Claude to read the html-slideshow skill before building any HTML?

✓

Output location — Does it specify where to save the finished HTML file?

4

Prompt to type

⚠ Do the same for the html-slideshow skill first if you haven't already — the reverse engineer skill depends on it being installed.

Key prompts — copy and adapt

List recent sessions
Show me my recent sessions
Single session
Reverse engineer session local_[paste-your-session-id-here] and save the slide deck to my outputs folder
Multi-session project
Reverse engineer these sessions: local_[id1], local_[id2], local_[id3] — they are all part of the same project. Treat them as one continuous build and produce a single slide deck covering the whole thing.
With audience context
Reverse engineer session local_[paste-your-session-id-here] — the deck is for colleagues who know Cowork basics but have never built anything like this. Make sure every prompt shown is verbatim and copy-paste ready, not paraphrased.
Quality check

What a good output deck contains

The finished HTML slide deck should pass this test: could someone who's never built this follow the slides and recreate it in one session?

Full inventory slide
Every skill, connector, folder, uploaded file, and output file listed — nothing assumed or left implicit.
Step-by-step slides
Each step numbered, titled, with a plain-English instruction and a clean reusable prompt — not a verbatim transcript copy.
Dead ends stripped out
Only the path that worked. The original session may have had wrong turns — the deck should show the shortest route, not a transcript replay.
Tips & watch-outs
Gotchas from the original build surfaced explicitly — so the next person doesn't hit the same wall.
Tips

Getting the best results

→

Run the skill after the work is done — transcripts can't capture sessions that haven't happened yet

→

Give Claude all session IDs upfront for multi-session projects — it reads them in parallel

→

Tell Claude who the audience is — "colleagues who know Cowork basics" vs. "complete beginners" changes the tone significantly

Watch-outs

⚠

If the output HTML doesn't look right, check that your html-slideshow skill is installed correctly — the reverse engineer skill reads it to know how to build slides

⚠

Long sessions (50+ messages) may need two transcript reads — the skill handles this automatically with limit and offset

⚠

The output deck describes the build — it doesn't recreate it. The reader still needs to run the steps themselves

Going further

Sharing the skill with others

Once your skill is working, you can share it with your whole team — each person installs it into their own Cowork.

Step 1 — Find the .skill file
After packaging, Claude presents a card with a "Save skill" button. The file is also saved to your Cowork folder — look for reverse-engineer.skill.
Step 2 — Send it
Attach the .skill file to a message (Slack, email, etc.) and send to your colleague. The file is small — typically under 10KB.
Step 3 — Colleague installs
They open the file in their Cowork session — a "Save skill" button appears. One click installs it.
Remember: share both
Your colleague also needs the html-slideshow.skill file. Package and send both together — the reverse engineer skill depends on it.
